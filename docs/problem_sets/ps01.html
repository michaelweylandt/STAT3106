2 \(K\)-Nearest Neighbor Methods (5 points)

In class, we introduced most of our ML concepts through one foundational method (OLS). In this assignment, we are going to compare OLS with a very different, but no less foundational, method called \(K\)-Nearest Neighbors (K-NN).

K-NN formalizes a simple idea: to make a prediction, remember what happened at the most similar point in the past. Specifically, when given a new point \(\tilde{\bx}\), we can search our training data for the ‘most similar’ point \(\bx_{\text{NN}}\) and use its label as our prediction for \(\tilde{\bx}\): \(\hat{y} = y_{\text{NN}}\). This is one nearest-neighbor prediction (1-NN) because we found the one most similar point from our training data. In practice, we usually find several similar points (3, 5, or 7) and take their average to make our predictions. This is a bit less messy (random) than using a single point, while still being nearly as flexible as 1-NN.

The \(K\)-NN family of methods is opposite to OLS in many ways:

  • While OLS reduces the (potentially) large training data down to a few coefficients, \(K\)-NN has no coefficients
  • Making predictions with OLS is easy (just a few multiplications and additions) while making predictions with \(K\)-NN can be slow if we have to review the entire training set every time we want to use it
  • When fit to non-linear relationships, OLS necessarily loses some information (by forcing things into a single plane) while \(K\)-NN can fit any shape with enough data.2

4 Estimating Out of Sample Performance with Cross-Validation (20 points)

Recall that our primary focus in this course is on developing models that perform well out-of-sample, i.e., on new ‘test’ data. Unfortunately, we do not always have an unlimited supply of ‘new’ data we can use for model evaluation and instead have to find a way to use our existing data for both model fitting and model evaluation. Doing this correctly can be a bit tricky: we want to avoid testing the model on data it has already seen so we don’t give it credit for ‘teaching to the test.’

But the fix is not too hard! We can split our data into two parts and use one for model fitting and the other for model evaluation in lieu of ‘true’ test data. The ‘golden rule’ here is simple: what is used to fit a model cannot be used to evaluate it and vice versa. In general, fitting a model is harder than simply estimating its out-of-sample accuracy, so we don’t use a straight 50/50 split, but it’s hard to give a universal guideline.3 This is known as the hold-out method.

One criticism of the hold-out method is that it can be a bit wasteful and a bit random. If we set 40% of our data aside for the holdout set, we are fitting our model on only 60% as much data as we would hope to and this can make our predictions much worse.4 With ‘large enough’ data, this may not be a problem, but ‘large enough’ is always relative to the model being fit and we would rather use a large data set to fit a flexible and powerful model; in other problems, data is scarce and spending 25-40% on model testing can significantly impair our ability to fit models at all.

The method of [cross-validation](https://en.wikipedia.org/wiki/Cross-validation_(statistics) (CV) attempts to address some of these limitations. Rather than performing a single split, we first:

  • Split the entire data set into \(K\) chunks of (roughly) equal size;
  • For \(k = 1, \dots, K\):
    • Set one chunk aside for model evaluation
    • Use the other \(K-1\) chunks to fit the model
    • Evaluate the model on the ‘set aside’ chunk and record the prediction error
  • Average the prediction errors to get the cross-validation estimate of prediction error. (It is also a good idea to put an error bar on this average.)

Visually,

Note that because the model being evaluated is a bit different each of the \(K\) times, it’s best to think of cross-validation as estimating the accuracy of a class of models rather than a single model. (‘How well does linear regression do on this problem?’ rather than ‘How well will this specific line do?’)

5 Using Cross-Validation for Model Selection (15 points)

Another use of cross-validation is selecting certain ‘hyperparameters’. Hyperparameters in this context refers to decisions that are made before the model encounters data: e.g., we might pre-select which features to include in a linear model before we actually use our data to estimate the regression coefficients.5 Recalling our ‘north star’ of optimizing predictions, we can try a reasonable range of values for a hyperparameter and pick the one that gives the most accurate cross-validation predictions.

There is, however, a slight risk here as the CV error we get is not an unbiased estimate of the true prediction error. Remember: if we pick the values of the model parameters to minimize our loss, we expect our future loss to be a bit worse; the same logic applies to selecting hyperparameters. To avoid this, we should use a combination of CV + holdout.

6 Estimating LOCO Feature Importance (15 points)

In certain applications, it may be important to interpret or explain the output of an ML model. Because different models work differently and different users require different types of interpretations, this is a challenging task for which a variety of methods have been proposed.6 In this sub-problem, you will explore a basic strategy sometimes called LOCO (Leave-One-Covariate-Out) feature importance.

The idea of LOCO is simple: a model is fit with and without a given feature and compare its performance. If the performance of the model falls when a feature is omitted, it is important; if the performance doesn’t significantly change, the feature is probably not too important to the model (or can be ‘replaced’ by other features in the data). Since, as always, we are interested in out-of-sample performance, the LOCO score is typically computed within a cross-validation scheme, rather than simply comparing in-sample error.
